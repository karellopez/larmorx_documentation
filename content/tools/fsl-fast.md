## What it is

FAST models the intensities of a skull-stripped brain as a mixture of tissue classes, each a Gaussian (three by default: CSF, grey matter and white matter, in the order of their intensity on a T1w), and finds the class of every voxel by expectation-maximisation with a hidden Markov random field that favours neighbours of the same class. It starts from a k-means of the brain's intensities (or from given intensities, `-s`, or from FSL's tissue priors registered onto the image, `-a`), estimates a smooth multiplicative bias field along with the classes and divides it out at each iteration, and ends with the partial volume of each tissue in each voxel: the fraction of CSF, grey and white matter a voxel at a boundary holds, from a second random field over the mixtures of neighbouring classes. Its outputs: the segmentation (`_seg`), the partial-volume maps (`_pve_0` to `_pve_2`) and their segmentation (`_pveseg`), the mixel types, and on request each class's posterior probability (`-p`), its binary image (`-g`), the bias field (`-b`) and the corrected image (`-B`); with `-S n` it segments several registered images together.

fMRIPrep calls it once per subject, on the T1w its brain extraction made (denoised, N4-corrected and skull-stripped), in its anatomical workflow (`anat_fit_wf/fast`): `fast -I 0 -N -p -g -S 1 <T1w brain>`, without a bias field (N4 corrected it before). Its partial-volume maps become the CSF, grey- and white-matter probability maps fMRIPrep writes (`label-CSF_probseg` and the others), from which its CompCor masks are made.

```bash
larmorx fsl fast -I 0 -N -p -g -S 1 T1w_brain.nii.gz             # fMRIPrep's call
larmorx fsl fast -b -B -o out T1w_brain.nii.gz                   # the bias field and the corrected image
larmorx fsl fast -S 2 -B -o out T2w_brain.nii.gz T1w_brain.nii.gz   # two channels (channel 1 named last)
```

```python
import larmorx as lx

r = lx.fsl.fast("T1w_brain.nii.gz", bias_iterations=0, no_bias=True, probabilities=True,
                segments=True)
csf, gm, wm = r.partial_volumes   # lx.Image each, on the input's grid
labels = r.segmentation.data      # 1 CSF, 2 grey matter, 3 white matter, 0 outside the brain
```

FSL is distributed under the FSL Licence, which allows non-commercial use only, so LARMORX keeps its FSL tools in two implementations: the exact replica translated from FSL's source, in the separate package `larmorx-nc` (`pip install larmorx-nc`), and a clean-room original in LARMORX itself, written from a behavioural specification without FSL's code. `implementation="auto"` (and `larmorx fsl fast`) runs the replica when `larmorx-nc` is installed and the clean-room original otherwise; `implementation="original"` (on the command line `LARMORX_IMPLEMENTATION=original`) chooses the original. The clean-room original is written from FAST's behavioural specification ([specs/fast.md](repo:specs/fast.md)), the paper (Zhang, Brady and Smith, IEEE TMI 2001) and black-box runs of FSL's program, never from FSL's code: every option, message, exit status and failure case, one channel or any number of them (`-S 9` and more too, which the replica refuses), the tissue priors registered by FLIRT's clean-room original in the same process, `exp` and `log` correctly rounded on every platform by default and as glibc 2.35 computes them in `reproduce` mode (below). It is built for speed: the random field's sweeps keep FAST's in-place order and run as a pipeline of planes that gives the one-thread result bit for bit at any thread count, FSL's blocked sums run block by block in parallel in their order, the partial volumes' 3 + 3 × 101 likelihoods per voxel go through a batched `exp` with the scalar function's bits (below, *Speed*). The replica follows FSL 6.0.7.23, runs none of FSL's programs and needs no FSL installation (with `-a` it registers the priors with FLIRT's replica, in the same process); its FSL libraries (newimage, the C library's random numbers and maths as FSL's build calls them, Armadillo 14.2.1's matrix arithmetic on OpenBLAS's LAPACK for several channels) are those every FSL replica of `larmorx-nc` shares with mcflirt, BET and FLIRT. How to read what follows: [the validation guide](/validation/#reading).

**The C library's last digits (since 2026-11-04).** FSL takes `exp` and `log` from glibc, the C library of Linux, whose results are now and then one unit in the last place from the exact value rounded once. LARMORX computes them correctly rounded, the same on every platform, and until 2026-11-04 the clean-room original did so in both modes, so it gave what FSL computes with correctly rounded maths (*identical with correctly rounded maths*) rather than FSL's own bits. Since then its `reproduce` mode computes them exactly as glibc 2.35 does, with LARMORX's versions of glibc's functions (`larmorx_core::math`): on fMRIPrep's three calls and on every single-channel case of its record it now gives FSL's files bit for bit (36 cases moved from *identical with correctly rounded maths* to *bit-identical*), while its default mode still gives, bit for bit, what FSL computes with correctly rounded maths (the examples' row *clean-room original, default − FSL, correctly rounded maths*). The two modes therefore differ by FSL's own last-bit band, a *deliberate correction* of the default (GLIBC-07 in the [register](repo:docs/findings/upstream-defects.md)) that FAST does not name: whether a segmentation moved with such last bits cannot be told without running it twice (the user's decision of 2026-11-04).

**The clean-room catch-up (2026-11-05).** The specification's answers of 2026-11-03 ([specs/fast.md](repo:specs/fast.md) §12) are now in the clean-room original, every example below run again with it. Its default corrects FSL-202 (with one channel, each class's variance in the logarithm of the intensities subtracts the square of the double-precision mean, where FAST's single-precision square cancels most digits) and FSL-203 (an image whose first voxel is NaN: the intensity extrema taken over the values that are numbers), named, as the replica's default does; its reproduce mode gives FSL's. The record holds the default to the replica's default: with glibc's `exp`, `log`, `expf` and `logf` in the default in place of the correctly rounded ones, the two defaults give the same bits on every single-channel case of the suite, so the examples' new row *clean-room original, default − replica, default* is the correctly rounded functions' last bits alone, no larger than FSL's own last-bit band but on the three channels, where it is just beyond it (976 partial-volume values against FSL's 973). Also from the answers: `_restore` stays NaN at NaN voxels unless FAST's rule for negative values ran; the lines FAST writes before an abort, as its C library buffers them; a class without weight in several channels (FSL's `MEAN -nan` lines, a permanent case). The record gained 13 cases of the original's own (`original/`: standard output at FAST's aborts and before the images are read, the NaN voxels of `_restore`), every one within the thresholds or rejected by both alike.

## The bias field {#bias}

FAST's default, which fMRIPrep's call turns off: the bias field estimated along with the classes, in the logarithm of the intensities (where a multiplicative field adds), from each voxel's residual against the class means weighted by its posteriors, smoothed by a Gaussian (its extent `-l`, 20 mm by default), and removed at each iteration (the record's case `opt/bias-outputs`, on the same T1w at half resolution). ## FSL's tissue priors (-a), and a correction by default {#priors}

With `-a` and a standard-to-input matrix, FAST brings FSL's tissue priors (avg152T1's CSF, grey- and white-matter maps) onto the image with FLIRT and starts the segmentation from them (the record's case `priors/a-verbose`, on MNI152NLin2009cAsym's T1w). The clean-room original registers the priors with FLIRT's clean-room original in the same process: its reproduce mode gives FSL's result bit for bit (since 2026-11-04; FSL's with correctly rounded maths before), its default mode makes the same correction.

## Speed {#speed}

FSL's `fast` is single-threaded. On fMRIPrep's call the clean-room original takes 2.4 to 5.2 s on one thread, 9 to 11 times faster than FSL, and 0.4 to 0.9 s on 14 threads, 47 to 67 times; the replica, a translation, is 1.4 to 1.9 times faster than FSL's build ([the report](repo:docs/benchmarks/fsl-fast.md): informal, one run each, on a machine shared with another job; FSL's time is its run stored by the oracle cache, not run again). The original's results are the same bits at any thread count; its peak memory on fMRIPrep's call, as the memory test measures it at one thread, is 152 MiB against FSL's 707.

## Corrections by default {#corrections}

The replica corrects FSL's deterministic defects by default and warns, with `upstream_defects="reproduce"` (`LARMORX_UPSTREAM_DEFECTS=reproduce`) giving FSL's behaviour byte for byte where FSL's is defined ([register](repo:docs/findings/upstream-defects.md)). `-p`'s probability maps outside the brain mask (and everywhere with `--nopve` and priors, or without an initialisation iteration) are memory FAST never writes: the replica writes 0 there in both modes and names it (FSL-96); fMRIPrep's call meets it (FSL's maps held zeros there in its three runs of the record; in two multi-channel cases one file held other values, which the record sets to 0 before comparing). With several channels and `-N`, the bias field `-b` saves and `-B` divides by is never computed: no field in both modes (FSL-97). With several channels, FAST's sort of the classes gives a class another class's covariance and posteriors when the classes move in a cycle (given intensities in a cyclic order, for example): each class keeps its own by default (FSL-98). A smoothness that is not a number, a bias smoothing of 0 or less and fewer than one class are refused by default, with the reason (FSL-99; FAST uses them as given or aborts). FAST aborts when `FSLDIR` is unset, even without priors: the replica segments (FSL-100). When FLIRT cannot register the priors, FAST says they are not used and then crashes on priors it never allocated: the replica segments without them (FSL-101). `-a` runs FLIRT through the shell with the names unquoted: the replica passes each name whole (FSL-102). The brain mask leaves out the voxels of the image's maximum when it is 2^24 or more: corrected (FSL-103). Channels of different sizes, which FAST reads past their ends, are refused in both modes (FSL-104). Since 2026-11-03, with the specification's answers to the clean-room original's questions: with one channel FAST takes each class's variance in the logarithm of the intensities as the mean of the squares minus the square of a single-precision mean, which cancels most of its digits; the replica's default squares the mean in double precision (FSL-202: it changes the default outputs of fMRIPrep's call, toward the exactly computed statistics, as the examples show); an image whose first voxel is NaN gives FAST NaN intensity extrema and an empty brain mask, and FAST stops with exit status 255: the replica's default takes the extrema over the values that are numbers and segments it (FSL-203). Inside `-a`, FLIRT's replica corrects its own defects too (FSL-09, above). The clean-room original makes the same corrections by default with the same notices (FSL-202 and FSL-203 since 2026-11-05), and its reproduce mode follows FSL where FSL's behaviour is defined (for a NaN `-H`, FAST's estimate of the smoothness; FSL-98's pairing; FSL-101's runs and aborts; FSL-102's split of the names; FSL-104 refused in both modes); inside `-a`, FLIRT's clean-room original corrects FSL-09 as the replica does. The clean-room original's default also computes `exp` and `log` correctly rounded, and its reproduce mode as glibc 2.35 does (GLIBC-07, named nowhere: *The C library's last digits*, above).

## Known limits {#limits}

Both implementations are experimental. Each record's standard tier holds fMRIPrep's calls on three oracle runs; the full tiers (fMRIPrep's call on every oracle run), the data panel's other images and long random testing run in the final validation phase. The clean-room original is held to thresholds, not to FSL's bytes: with several channels its own matrix arithmetic leaves a few partial volumes one fraction step from FSL's, and nearly singular covariances (five channels, two of them nearly a combination of the others) are decided by the arithmetic's last bits; the single-channel variance in the log domain cancels most digits, which makes FSL's own band wide on small classes: measured since (2026-11-03), it is a defect of FAST, FSL-202, corrected by default in both implementations (the clean-room original's since 2026-11-05, held to the replica's default). Open from the catch-up's trial: which program aborts on a class covariance singular in exact arithmetic, and several channels whose reproduce run parts from FSL's (four random cases). More than eight channels (`-S 9` and more): the clean-room original segments them; the replica refuses them in both modes with a message, as FSL's results there follow OpenBLAS's kernels for larger matrices, which it does not reproduce. With several channels whose covariances turn NaN (an empty class), a NaN can carry other payload bits than FSL's (the values and their NaN-ness are FSL's). Two behaviours of the multi-channel segmentation are kept as FAST's until they are measured on real T1w and T2w pairs: its initialisation, which pairs each channel's classes in the order of that channel's own intensities (channels of opposite contrast can start from empty classes, and FAST then ends with every voxel in one class), and its bias field. The other five platforms are held to LARMORX's own Linux output by the [golden tests](repo:docs/validation/golden.md) (the clean-room original: fMRIPrep's call, the bias field, two channels, the priors, the defects' switches and a 2D image). The benchmark is informal: one run each, on a shared machine.
